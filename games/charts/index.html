    Sharing

    Charts & the library

    A .signal file holds the note chart and the song itself, so anyone who opens one can play immediately — no separate audio file to hunt down.

    Make one

    Load an audio file, let the detector rough out a chart, then open the editor to fix what it got wrong — drag notes around, tap them in live against the music, or clear a mode and hand-place every one. Export when you are happy and you get a single file to send to anyone.

    Serve a folder of them

    Put index.html on any web server and drop .signal files in beside it. Because a server answers a request for that folder with index.html rather than a file listing, charts sitting next to the game need naming in an index.json — a plain list of filenames:

    index.html hold-music-2026.signal index.json ["hold-music-2026.signal"]

    Run this from that folder and the manifest writes itself:

    ls *.signal | python3 -c "import sys,json;print(json.dumps(sys.stdin.read().split()))" > index.json

    Prefer no manifest at all? Make a charts subfolder instead. There is no index file in the way, so the server lists it and the game reads that listing — drop files in and they appear. Both places are checked, so you can use either or both.

    index.html charts/ ├─ hold-music-2026.signal └─ track-3-remix.signal

    Static hosts like GitHub Pages and Netlify never list directories, so use index.json on those. Only the file header is read while browsing, so the song data downloads when someone actually picks a chart.
